# ゲスト利用 実装・導入ガイド

更新日: 2026-09-30

## 目的

アカウントを作る前でも、マチノワ室蘭の主要な体験を試せるようにします。

- ロボット（ボルタ / ナッティ）を作る
- 作成中のロボットを使ってジオラマを作る
- ECデモで商品をカートに入れ、ゲスト購入を完了する
- 後からログイン / 新規登録し、ゲストで作ったロボットとジオラマを正式保存する

ゲスト状態そのものをSupabaseユーザーとして作成する方式ではありません。未ログイン状態の一時ワークスペースとして実装しています。

## ゲスト作品の保存範囲

PC React版では、ゲストのロボットとジオラマを `sessionStorage` に一時保存します。

- 同じタブでの画面移動・再読み込み: 復元可能
- タブを閉じる: 原則として消える
- 別タブ / 別端末: 引き継がない
- Supabase: ログイン前は書き込まない

一時ロボット / ジオラマにはUUIDを割り当て、ログイン後の「アカウントへ保存」で同じIDのまま `saved_robots` / `dioramas` へ保存します。途中で保存処理が失敗しても、同じIDで再試行できるよう `upsert` を使っています。

## ゲストジオラマ

未ログインでは保存済みロボットが存在しないため、ロボット工房のゲストロボットを一時的な `SavedRobot` としてジオラマへ渡します。

- ゲストロボットをジオラマへ配置可能
- ジオラマも同じタブへ一時保存
- ログイン後、ロボットを先に正式保存してからジオラマを保存
- ゲスト中の自作アイテム保存・ジオラマ配置は対象外（ログイン後に利用）
- ガチャ限定背景は、未取得のゲストには開放しない

## ゲスト購入

PC版とスマホ互換版に `/api/guest-purchase` を追加しています。

配送先として以下を購入確認時に入力します。

- 氏名
- 郵便番号
- 住所
- 電話番号

このアプリケーションは、ゲスト配送先をSupabase DB、Cookie、`localStorage`、`sessionStorage`へ永続化しません。成功レスポンスにも配送先を含めません。

商品金額・送料はサーバー側の商品カタログから再計算し、クライアントから合計金額を信用しません。ゲスト購入ではポイント付与はありません。

現在のサイトはECデモのため、ゲスト購入はDBへ実注文レコードを作らず、注文番号を使った完了表示までを行います。実配送・実決済へ移行する場合は、配送に必要な個人情報の保持期間・削除方針・決済事業者連携を別途設計してください。

## ログイン後の引き継ぎ

ゲスト作品が残っている状態でログインすると、マイページ上部に「ゲスト作品を引き継ぐ」が表示されます。

- `アカウントへ保存`: ロボット → ジオラマの順に正式保存
- `ゲスト作品を破棄`: 確認ダイアログ後、一時作品を削除

メール確認が必要な新規登録の場合は、確認後に同じタブでログインしてから引き継ぎます。

## ログインが必要な機能

以下は引き続きアカウントが必要です。

- 作品の永続保存（引き継ぎ前）
- お気に入り
- ポイント獲得
- ガチャ
- 自作アイテムの永続保存とゲストジオラマへの配置
- ジオラマ公開 / ギャラリーへの投稿
- 壁画レビュー投稿・いいね等の本人操作

## スマホ互換版の範囲

既存のスマホ互換モードの制約を維持しています。

- ゲスト商品閲覧・カート・ゲスト購入: 対応
- 2Dロボット作成: 利用可能（URLパラメータによる軽量編集）
- 自由配置ジオラマ編集: 従来どおりPC版のみ
- ゲスト作品の `sessionStorage` 自動引き継ぎ: PC React版を中心に対応

## Supabase / SQL

この機能のための追加SQLはありません。

既存の `saved_robots` / `dioramas` とRLSをそのまま使い、ログイン後の引き継ぎ時だけ本人の `user_id` で保存します。ゲスト中はSupabaseへ作品を書き込みません。

## 検証

`npm run validate:guest` でゲスト機能専用の静的検証を実行できます。

主な確認内容:

- sessionStorageのみを使う一時作品
- ログイン前のDB保存を行わない設計
- ログイン後のUUID維持import
- ゲストロボットを使ったジオラマ編集
- ゲスト購入のサーバー側金額再計算
- 注文DB / Supabase購入RPCからの分離
- 配送先を成功レスポンスへ含めないこと
- ポイント0
- PC / スマホ双方のゲスト購入導線
