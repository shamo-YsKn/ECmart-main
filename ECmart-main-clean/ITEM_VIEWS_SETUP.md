# アイテム工作：正面・側面・背面対応（2026-09-24）

ロードマップ③「アイテム工作においての正面・側面・背面」を実装した更新です。②の左右側面対応とフェーズ6を含む版を基準にしています。

## 今回の設計

方向ごとに別々の絵を保存する方式にはせず、1つのパーツ配置を3方向へ直交投影します。

- X = 左右
- Y = 上下
- Z = 奥行き（+Zが正面側）
- 正面 = X / Y
- 側面 = Z / Y
- 背面 = -X / Y

`CustomItemDocument.coordinateSpace` は新規保存で `item-workbench-v2` になります。旧 `item-workbench-v1` はX/Y位置とZ回転をそのまま保持してv2へ読み込むため、従来の正面作品を一括変換する必要はありません。

## 工作台の操作

工作台上部に「正面 / 側面 / 背面」を追加しました。

- 正面でドラッグ：X/Yを編集し、Zを保持。
- 側面でドラッグ：Z/Yを編集し、Xを保持。ここでパーツに奥行きを付けられます。
- 背面でドラッグ：実物を後ろから見た左右反転表示でX/Yを編集し、Zを保持。
- 正面・背面の回転はZ軸、側面の回転はX軸として保存。
- 選択中パーツにはX/Y/Zを表示。
- 完成イメージに正面・側面・背面の3プレビューを同時表示。

## パーツ形状

既存11種類について正面図を維持し、側面用のシルエットを追加しました。背面は正面形状を実物の後ろ側として左右反転します。

各パーツには将来の3D化に使える基準奥行き `depth` を追加しています。現段階は本格3Dメッシュではなく、2D/2.5Dの直交投影です。

## スナップ接続

従来は正面の2D座標だけで接続点を計算していました。今回からsocketを3D座標へ変換してから現在のビューへ投影します。

- 正面・側面・背面のどこでも同じsocketを使用。
- 接続時はX/Y/Zの3軸でsocket位置を一致。
- 親を動かしたときの子パーツ追従も3D移動。
- 回転・拡大縮小後の再配置も3D位置で再計算。

既存socketはZ=0として扱うため、従来作品の正面スナップ仕様を保ちます。

## ロボットへ持たせた場合

自作アイテムはロボットの表示方向へ追従します。

- ロボット正面 → アイテム正面
- ロボット背面 → アイテム背面
- 左右側面 → アイテム側面

右側面ではロボット全体の鏡像に合わせ、アイテム内部の手前/奥の描画順も逆転させます。装備する手や保存IDは変更しません。

## Supabase

追加SQLは不要です。`custom_items.document` はJSONBで保存しているため、v2のX/Y/Zと3軸回転をそのまま保持できます。

既存の `supabase/custom-items-migration.sql`、フェーズ6SQL、左右側面SQLはこれまでどおりです。

## 現時点の限界

これは本格3D工作ではありません。各パーツの側面は3D化へつなぐための2Dシルエットで、自由なカメラ角度や透視投影、実メッシュの衝突判定はPhase 7の対象です。

ただし、位置をX/Y/Z、回転をX/Y/Z、サイズを3要素、接続点を3D座標として保持する土台へ移行したため、3D化時に方向別の2D作品を再統合する必要はありません。
