# フェーズ6：作品共有の導入・操作ガイド

## 今回追加した機能

- ジオラマの公開／非公開、作品名・説明文、明示的な公開内容の更新。
- 公開時点の背景・配置・ロボット・持ち物を保持するスナップショット。
- ギャラリー、新着順／いいね順、作者の作品一覧、作品詳細、ページ送り。
- ログインユーザーのいいね／取り消し（1人1作品1回）。
- 壁画レビューの本人編集。
- 作品・壁画レビューの通報、管理者の通報確認・非表示・非表示解除・対応不要処理。
- 管理操作の対応理由と履歴保存。
- スマホ互換表示でのギャラリー閲覧、作者一覧、いいね、作品通報。JavaScriptなしのフォーム送信にも対応。

既存の自由ポーズ計算、工房、カート、ポイント、ガチャの仕様は変更していません。保存済みデータを一括公開する処理もありません。

## 1. 既存環境への導入

1. 現在のプロジェクトとデータベースをバックアップしてください。
2. 更新版のコードへ切り替えます。現在使っている `.env.local` は引き継いでください。このZIPには認証キーや実データは含めていません。
3. SupabaseのSQL Editorで `supabase/phase6-community-migration.sql` を実行します。
4. プロジェクトのフォルダーで次を実行します。

```powershell
npm ci
npm run check
npm run build
npm run dev
```

追加SQLは、Phase 5までの環境があることを前提にしています。少なくとも `profiles`、`saved_robots`、`custom_items`、`dioramas`、`mural_posts`、`mural_post_likes` が必要です。

まだ設定していない場合は、既存の `SUPABASE_SETUP.md` に従ったうえで、自作アイテム・ジオラマ・壁画の各migrationを先に実行してください。Phase 6のSQLは最後に実行します。古い壁画SQLをあとから再実行すると公開権限の設定が戻るため、その場合は必ずPhase 6のSQLを再実行してください。

Phase 6のSQLはトランザクションで実行され、再実行可能です。既存の制作テーブルの形式は変更せず、新規テーブル・関数・壁画の公開権限を追加／更新します。

接続設定がない場合やSQL未適用の場合は案内を表示します。未接続状態で公開・いいね・通報の成功を表示することはありません。

## 2. 管理者の登録

通報対応を行う人のアカウントを作成し、SupabaseのAuthentication > Usersで対象のUUIDを確認してください。

SQL Editorで次のUUID部分を置き換えて実行します。画面の表示名やメールアドレスではなく、確認したユーザーUUIDを使います。

```sql
insert into public.community_moderators (user_id)
values ('対象ユーザーのUUID'::uuid)
on conflict do nothing;
```

対象アカウントでPC版へログインし直すと、マイページに「投稿管理（管理者）」が表示されます。一般ユーザーが自分を管理者に登録する経路はありません。

通報対応画面では、未対応／対応済み／対応不要を切り替え、投稿内容と通報理由を確認できます。非表示・解除時は理由入力と確認が必要です。操作履歴は `community_moderation_audit` に保存され、SQL Editorから確認できます。通報者の情報・通報理由・管理履歴は一般公開しません。

公開運用を始める前に、必ず通報を確認する管理担当者を決めてください。

## 3. 作品を公開する

1. 工房でロボット・自作アイテムを保存します。
2. ジオラマを作り、保存します。
3. PC版マイページの「マイジオラマ」で「公開設定」を開きます。
4. 作品名（40文字以内）・説明（1000文字以内）を入力します。
5. 「公開する」を押して確認すると、全員がギャラリーから閲覧できます。

公開時にサーバーが本人の保存済みデータを読み、作品に必要なロボット・配置アイテム・手に持つ自作アイテムをコピーします。無関係な所持品は公開しません。他人の非公開素材への参照が含まれていると、公開は失敗し、前の公開内容が維持されます。

## 4. 公開後の変更

- 工房で下書きやロボットを編集しても、展示中の作品は変わりません。
- 工房で保存した後、マイページの「公開内容を更新する」から反映します。
- 更新時は作品IDといいねを維持します。新着順は初回公開日時を基準とし、更新のたびに先頭へ上がりません。
- 「非公開に戻す」で公開一覧・作品詳細・他人からの直接参照を停止します。制作データといいねは残ります。
- マイジオラマ自体を削除すると、公開作品といいねも削除されます。確認ダイアログで説明します。
- 管理者による非表示は、作者の編集や公開更新では解除できません。
- 管理者が非表示を解除しても、作者が非公開にしている作品は公開されません。

すでに閲覧者が取得・撮影した内容を非公開操作で回収することはできません。個人情報など公開すべきでない内容は作品名や説明に入力しないでください。

## 5. 壁画レビューと通報

PC版のまち歩きで自分の投稿を開くと「レビューを編集」が使えます。本文を400文字以内で編集でき、ロボット・配置・いいねは維持します。

他人の作品／壁画投稿には「この投稿を通報」を表示します。ログインが必要です。理由は500文字以内で、同じ人から同じ投稿への重複通報はまとめます。新規通報は1人24時間で20件までです。通報だけで自動的に削除しません。

管理者により非表示の壁画投稿は、一般閲覧とスマホ公開表示から除外します。投稿者本人には編集・削除のため表示し、非表示中である旨を案内します。

## PC版とスマホ互換表示の範囲

| 機能 | PC版 | スマホ互換表示 |
| --- | --- | --- |
| ギャラリー・作品詳細・作者一覧・新着／いいね順 | 対応 | 対応 |
| ジオラマへのいいね・取り消し・通報 | 対応 | 対応 |
| ジオラマの制作・公開設定・公開内容更新 | 対応 | PC版を使用 |
| 壁画レビュー編集・通報 | 対応 | 今回は未追加 |
| 管理者の通報対応 | 対応 | PC版を使用 |

スマホの新機能は、既存のサーバー表示とフォーム送信を利用しています。メニューは項目が増えたため横スクロールに対応しました。

## 検証と未確認範囲

`npm run check` は既存の全検証に加え、独立したPostgreSQLエンジンでPhase 6のSQLと権限を検証します。テスト用データはその実行内だけで作られ、実際のSupabaseには接続しません。

今回、型チェック・既存validator・データベース44項目・本番ビルドが通過しました。テスト用APIと接続したNext.jsでPC／スマホのHTTP応答、いいね・通報のフォーム送信も確認しています。一方、検証用ブラウザが環境上起動できなかったため、クリック操作と画面の見た目の自動検証は未完了です。

この更新では、本番SupabaseへのSQL適用・管理者登録・本番サイトへのデプロイは行っていません。導入後、別ユーザーとゲストで実環境の操作確認を行ってください。季節限定壁画、イベントスポット、コメント、フォロー、通知、実地図API、3D高度化は今回の対象外です。
