# ⑤-1〜⑤-4 イメージ提案機能 実装メモ

更新日: 2026-10-01

## 概要

外部AI APIを使わず、文章からボルタ／ナッティの構成候補を提案する初版を実装した。

処理フロー:

1. ユーザーが作りたいイメージを文章で入力
2. `lib/robot-idea-engine.ts` がキーワード・明示指定を解析
3. 現在利用可能な部品・色だけを使って3候補を生成
4. 候補ごとに既存の `price-estimator` で参考価格を表示
5. 「この案で作る」で既存 `RobotConfig` に変換してロボット工房へ反映
6. その後は通常どおり色・ポーズ・自由ポーズ・持ち物・保存を編集可能

## ⑤-1 提案UI

PC版ロボット工房の上部に「イメージからボルタ・ナッティを提案」カードを追加した。

- 240文字まで入力
- サンプル入力ボタン
- 3案を同時表示
- 各候補にテーマ、タイプ、ポーズ、持ち物、向き、参考価格を表示
- 「この案で作る」で工房へ即反映

スマホ互換表示にもGETフォーム型の同機能を追加した。スマホ側はReact hydrationに依存しない。

## ⑤-2 ルールベース解析

現在は外部APIを使わない。

代表的な認識テーマ:

- 釣り
- 音楽・楽器
- 室蘭やきとり
- バイク・乗り物
- 工場・ものづくり
- 整備・工具
- 歯車・機械
- 花・園芸
- ハート・記念
- あいさつ
- お祝い・元気
- 案内・指さし
- シンプル・直立
- 写真・カメラ
- スポーツ
- ダンス
- 読書・勉強
- 魔法・ファンタジー
- 海・港
- 冬・雪
- アート・制作
- カフェ・給仕
- 天体観測
- 武将・忍者
- 料理
- プレゼント

明示指定がある場合はテーマ既定値より優先する。

- 「ボルタ」「ナッティ」
- 「正面」「右側面」「左側面」「背面」
- 「手を振る」「ばんざい」「指さし」「直立」
- 「スパナ」「歯車」「花」「ハート」
- 一部のボディ色／目の色

ガチャ未解放の色・持ち物は提案に強制使用しない。現在使える構成へ安全にフォールバックする。

## ⑤-3 工房への反映

候補は直接DOMや描画値を変更せず、必ず既存 `RobotConfig` に変換してから工房へ渡す。

そのため以下をそのまま利用できる。

- 既存保存形式
- ゲスト一時保存
- 自由ポーズ編集
- 左右側面
- 頭・目の向き
- 既存Supabase保存

提案を採用すると編集対象IDを解除し、新規案として工房へ読み込む。

## ⑤-4 参考価格連携

候補価格は `lib/price-estimator.ts` を再利用する。

- ボルタ基本価格: 1,150円
- ナッティ基本価格: 1,250円
- 標準色・標準ポーズ・既存持ち物は基本価格内
- 自作アイテムが将来候補として表示されても、未作成の段階では参考価格へ加算しない

例: 「釣竿を持つボルタ」を文章から提案した時点では、釣竿自体はまだ自動生成していないため、候補カードには「将来の自作アイテム連携候補: 釣竿」と表示する。⑤-5で工作データを生成した後は既存価格スコアで再計算できる。

## AI接続 ON/OFF

PC版には `AI接続 ON/OFF` の設定を追加した。

保存キー:

`machinowa:robot-idea-ai-enabled`

現在は外部AI接続先を実装していないため:

- OFF: ルールベース
- ON: 接続設定は保存するが、接続先未設定を明示しルールベースへフォールバック

`lib/robot-idea-engine.ts` 自体には `fetch()` や外部API URLを持たせていない。したがって現時点ではONにしても外部送信・API課金は発生しない。

将来は `requestedProvider = external` の経路に外部AIアダプタを追加し、同じ `RobotIdeaCandidate[]` 形式へ正規化してから既存の工房反映処理へ渡す。

## 検証

`npm run validate:idea-assistant`

で以下を検証する。

- 釣りテーマ認識
- ナッティ明示指定
- 右側面指定
- 工場テーマと歯車
- 未解放持ち物のフォールバック
- 解放済み色の反映
- 未解放色のフォールバック
- 楽器テーマと将来工作候補
- AI接続ON時のルールフォールバック
- 不明テーマでも3案生成
- 生成した全候補が `normalizeRobotConfig` を通る
- ルールエンジンに `fetch()` / 外部URLが存在しない
- PC / スマホ両UIへ接続済み
